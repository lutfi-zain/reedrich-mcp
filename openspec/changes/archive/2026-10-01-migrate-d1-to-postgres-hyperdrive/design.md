## Context

See `proposal.md` for motivation.

The current system relies on Cloudflare D1 (serverless SQLite at edge) bound as `c.env.DB`, using `drizzle-orm/d1` with schemas defined in `src/db/schema.ts` via `sqliteTable`. D1's Free tier enforces a 5,000,000 scanned row reads/day limit (`code: 7500`), which causes hard failures across queries once breached.

The host VPS (`VM-3-103-ubuntu`, IP `43.133.148.181`) already runs a hardened PostgreSQL 16 container (`postgres-primary` on `127.0.0.1:5432`) fronted by PgBouncer (`pgbouncer` on port 6432 with `DB_NAME=*` and transaction-level pooling), and an active Cloudflare Hyperdrive configuration (`id: 246e815964a44eed9464752afe346134`, `name: vps-pg`).

## Goals / Non-Goals

**Goals:**
- Create and provision a dedicated `reedrich` database in PostgreSQL with full table, constraint, and index parity for all 10 entities.
- Migrate Drizzle ORM schema from SQLite (`drizzle-orm/sqlite-core`) to PostgreSQL (`drizzle-orm/pg-core`).
- Transition Cloudflare Workers driver layer from `drizzle-orm/d1` to `drizzle-orm/postgres-js` leveraging Cloudflare Hyperdrive's managed edge connection pooling.
- Migrate existing production data (~3,469 rows across 10 tables) from D1 to PostgreSQL while strictly preserving IDs, hashes, timestamps, and foreign key relations.
- Modernize unit and integration test infrastructure to run against a dedicated local PostgreSQL database (`reedrich_test`) on the VPS, eliminating SQLite dialect discrepancies.

**Non-Goals:**
- Moving the application server out of Cloudflare Workers (the backend remains serverless on Cloudflare Workers edge).
- Changing REST API schemas, route paths, status codes, or MCP JSON-RPC tool contracts.
- Altering the business logic or arithmetic calculations for wallet reconciliations, debt repayments, or safe-to-spend projections.
- Dropping or truncating any data from the remote Cloudflare D1 database (Zero Remote Deletion Invariant).

## Decisions

### 1. Dedicated PostgreSQL Database `reedrich` via Dynamic PgBouncer Routing
- **Decision**: Create a dedicated database `reedrich` in PostgreSQL 16 (`docker exec postgres-primary psql -U postgres -c "CREATE DATABASE reedrich;"`) rather than reusing the default `postgres` database.
- **Rationale**: Keeps application finance data clean, isolated, and easily backable with `pg_dump -d reedrich`. Because PgBouncer is already configured with `DB_NAME=*`, it dynamically opens and pools connections to `reedrich` without requiring container restarts.
- **Hyperdrive Target**: Update the existing Hyperdrive configuration `vps-pg` via Wrangler:
  ```bash
  wrangler hyperdrive update 246e815964a44eed9464752afe346134 --database reedrich
  ```

### 2. Driver Selection: `postgres` (postgres.js) with `drizzle-orm/postgres-js`
- **Decision**: Use `postgres` (postgres.js) as the database client in Cloudflare Workers, instantiated via `drizzle(client, { schema })`.
- **Alternatives Considered**:
  - `node-postgres` (`pg`): Requires Node.js standard libraries (`events`, `stream`, `crypto`) polyfilled via `@cloudflare/workers-types`, which adds bundle bloat and potential edge incompatibilities.
  - `@neondatabase/serverless`: Tailored specifically for Neon WebSockets, not generic VPS PgBouncer TCP endpoints.
  - `postgres` (postgres.js): Natively supported by Cloudflare Workers over `cloudflare:sockets` and Hyperdrive (`env.HYPERDRIVE.connectionString`), lightweight, fast, and fully supported by Drizzle ORM.

### 3. Schema DDL & Type Alignment
- **Decision**: Translate `src/db/schema.ts` to `drizzle-orm/pg-core`:
  - `sqliteTable` ➔ `pgTable`
  - `text("...").primaryKey()` ➔ `text("...").primaryKey()` (storing UUID strings generated by `crypto.randomUUID()`)
  - `real("...")` ➔ `doublePrecision("...")` (maintaining exact IEEE 754 float precision matching the previous SQLite real column behavior for balances, amounts, and fees)
  - `integer("...")` for boolean flags (`wallet_is_locked`, `transaction_is_planned`, `template_is_active`) ➔ `integer("...").notNull().default(0)` (retaining 0/1 integers for 100% backward compatibility with Drizzle queries and JSON serialization)
  - Timestamps: `text("...").default(sql\`CURRENT_TIMESTAMP\`)` ➔ `text("...").default(sql\`CURRENT_TIMESTAMP\`)` (ISO-8601 strings normalized by `src/utils/date.ts`)
  - Foreign key cascades (`onDelete: "cascade"`, `onDelete: "set null"`) and indexes (`index()`, `uniqueIndex()`) preserved 1:1.

### 4. Zero Remote Deletion ETL Data Migration
- **Decision**: Run a deterministic migration script that reads all tables from Cloudflare D1 via Wrangler JSON query output (`wrangler d1 execute finance_db --remote --json`) and inserts them into PostgreSQL `reedrich` in strict dependency order:
  1. `users`
  2. `wallets`
  3. `categories`
  4. `budgets`
  5. `recurring_templates`
  6. `transactions`
  7. `debts_loans`
  8. `feedbacks`
  9. `goals`
  10. `goal_wallets`
- **Invariant**: The D1 database will NOT be dropped, truncated, or modified during or after migration. D1 remains read-only as a historical fallback.

### 5. Multi-Tenant RLS Enforcement Parity
- **Decision**: Retain mandatory `eq(schema.<table>.<table>UserId, userId)` predicate across every Drizzle query. The service layer remains transport-neutral; changing `db: DrizzleD1Database<typeof schema>` to `db: PostgresJsDatabase<typeof schema>` preserves identical query builder syntax (`eq`, `and`, `or`, `inArray`, `desc`, `asc`, `sql`).

### 6. Test Infrastructure: Real Local PostgreSQL Test Database
- **Decision**: Replace `MockD1Database` (which depended on `node:sqlite`) with a dedicated local PostgreSQL database `reedrich_test` on `127.0.0.1:5432`.
- **Rationale**: Running unit tests (`npm test`) and local integration tests (`npm run test:local`) against real PostgreSQL ensures 100% dialect fidelity, eliminates SQL translation bugs, and leverages the already-running Docker container on the host.

## Risks / Trade-offs

- **[Risk] Cold Starts & Connection Latency** -> Cloudflare Hyperdrive maintains a persistent pool of TCP connections from edge locations to the VPS PgBouncer, keeping connection handshake latency near zero. PgBouncer on the VPS handles pooling to PostgreSQL.
- **[Risk] Edge Runtime Compatibility with Driver** -> `postgres` (postgres.js) is validated and officially documented by Cloudflare Workers for Hyperdrive. Tested with standard `drizzle-orm/postgres-js`.
- **[Risk] Integration Test Disruption** -> `tests/integration.test.ts` is transport-agnostic (HTTP/JSON-RPC). Adapting the shell scripts (`run-local-integration.sh`, `run-integration.sh`) to PostgreSQL ensures the 4 mandatory test commands pass cleanly.
- **[Risk] Data Loss or Corruption during ETL** -> Data migration performs batch inserts wrapped in transactions, verifying row counts per table before cutover. D1 remote data remains untouched.
